# Deep Research

## 核心原则

**不要只搜一次就下结论。** 单次搜索永远不够。先广度覆盖，再对每个重要维度深挖，最后交叉验证。

## 搜索方法论

### 1. 广度探索
- 先用宽泛关键词搜索主题全貌（本项目的 `search` 工具会自动爬取全文并 embedding 过滤）。
- 从结果里识别出关键维度 / 子主题 / 不同立场，列出来。

### 2. 深挖每个维度
- 对每个重要维度换 2-3 种措辞再搜："[主题] 方法"、"[主题] 对比"、"[主题] 挑战"。
- 关键来源要拿到具体数字、案例、专家观点，而不是只有摘要。

### 3. 信息类型多样性
| 类型 | 目的 | 关键词提示 |
|------|------|-----------|
| 事实与数据 | 具体证据 | 统计 / 数字 / 市场规模 |
| 案例 | 真实落地 | 案例 / 实现 / 部署 |
| 专家观点 | 权威视角 | 专家 / 分析 / 访谈 |
| 趋势与预测 | 未来方向 | 趋势 / 预测 / 未来 |
| 对比 | 备选与背景 | 对比 / 与...区别 |
| 挑战与批评 | 平衡视角 | 局限 / 挑战 / 争议 |

### 4. 时间感知
- 永远用**当前年份**（来自系统注入的日期）构造查询，不要用训练数据里的旧年份。
- 问"最近/最新"时带上月份甚至日期，避免只搜年份丢精度。

### 5. 综合校验（开始写报告前）
- [ ] 至少 3-5 个不同角度搜过
- [ ] 拿到具体数据 / 案例 / 专家观点
- [ ] 正面与挑战/局限都覆盖
- [ ] 信息是当前年份且来自可靠来源
- 任何一项为否，就继续搜索，不要开始写。

## 常见错误
- ❌ 只搜 1-2 次就停
- ❌ 只搜一个角度
- ❌ 忽略反面观点
- ❌ 用过期年份查询
- ❌ 研究没做完就生成报告
